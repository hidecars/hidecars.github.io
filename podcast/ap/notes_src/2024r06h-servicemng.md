# 令和6年度春期 午後 問10 サービスマネジメント／テレワーク環境下のサービスマネジメント

## 1. 覚えるキーワード3つ
- SPOC：問合せ窓口を一つにまとめ、利用者が迷わないようにする仕組み
- エスカレーション：サービスデスクで解決が難しい問合せを、開発課などの専門部署へ引き継ぐこと
- 展開管理：テスト済みのOSパッチなどを、適用のタイミングを制御しながら確実に展開する管理

## 2. 状況
- E社が全営業員にタブレット端末を貸与し、社外から社内ITへ接続するテレワーク環境を作った。
- 利用開始の初期は問合せが多いため、開発課に初期サポート窓口を置き、安定したらサービスデスクへ一本化(SPOC化)する。
- 手動のパッチ適用で障害が再発しないよう、統合管理ツールでOSパッチを自動で適用する。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| 初期サポート窓口を終えて、サービスデスクへ一本化する | 期間が過ぎたことだけを理由にする（設問2(3)は正答率が低かった） | 開発課から、初期サポート内容の引継ぎと、窓口での対応内容の確認が完了していることを条件にする | 初期サポート内容の引継ぎが完了している |
| OSパッチを確実に適用したい | 統合管理ツールの機能(自動配信など)だけを述べる（設問3は正答率がやや低かった） | 展開管理の視点で、適用のタイミングを運用側でコントロールできることを理由にする | OSパッチの適用のタイミングをコントロールできる |
| 電話サポートに時間がかかる | — | 遠隔の端末を画面操作できるリモート操作の機能を使う | 電話によるサポートは時間が掛かる、リモート操作 |

## 4. 解答キーワード一覧

| 設問 | 問われていること | 決め手のキーワード |

| 1 | 空欄(a) | イ |
| 2(1) | 初期サポートを終える時の状態(b) | 収束した状態になる／サービスデスクだけでできる／定常状態に落ち着く |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| SPOC | 問合せの窓口を一つにまとめる仕組み |
| エスカレーション | 対応が難しい案件を専門部署へ引き継ぐこと |
| 展開管理 | 検証済みの変更やパッチを、計画的に確実に適用する管理 |
| 統合管理ツール | 端末の情報・ログ・パッチ適用を一元的に管理・操作するシステム |
| リモート操作 | 遠隔の端末の画面を共有して操作できる機能 |
| 初期サポート | 利用開始直後の問合せを手厚く受け付ける対応 |

## 6. 思い出しクイズ
- Q1 サービスデスクで解決できない問合せを開発課へ引き継ぐことは → エスカレーション
- Q2 問合せ窓口を一つにまとめる仕組みは → SPOC
- Q3 展開管理の視点で、パッチ適用機能を使う理由は → OSパッチの適用のタイミングをコントロールできるから
- Q4 遠隔の端末への電話サポートに時間がかかる問題の解決に使う機能は → リモート操作
- Q5 初期サポートを終えてSPOCへ移るとき、開発課から受ける完了事項は → 初期サポート内容の引継ぎ完了と、対応内容の確認完了

※採点講評：設問2(3)は正答率が低かった。設問3は正答率がやや低く、統合管理ツールの機能だけを述べた解答が散見された。
