# 令和5年度秋期 午後 問9 プロジェクトマネジメント／新たな金融サービスを提供するシステム開発プロジェクト

## 1. 覚えるキーワード3つ
- 内製か業務委託かの判断：自社の現状(機械学習を習得する時間がない)を正確に把握して、外部の技術支援を選ぶ
- ベンダーの比較評価：評価項目ごとに採点して比べる。このプロジェクトでは、定着化と使用性の両方が最高点のベンダーを選ぶ
- プロジェクト完了後の定着：外部に任せても、完了後に自社で使い続けられるかを考えて、役割分担と調達を決める

## 2. 状況
- 金融サービス業のA社は、顧客の流出を防ぐため、機械学習を使った新しいデジタル金融サービスを6か月以内にリリースする。
- 機械学習の経験が浅く、スコープの変更も頻繁に起こるため、アジャイル開発とPoCを採用し、ベンダーから準委任契約で技術支援を受ける。
- 設問は、採用した背景、ベンダー選定、契約形態、プロダクトオーナーの選定、PoCで測定するものを問う。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| 機械学習を自社でやるか委託するか | —（設問1(2)は正答率が平均的） | 他社の事例だけでなく、自社の現状を正確に把握する。機械学習技術を習得する時間がないので、技術支援を業務委託する | 習得の時間がない |
| ベンダーを選ぶ | —（設問2(1)は正答率がやや高かった） | 評価項目の点数で比較する。定着化と使用性の両方が最高点のQ社を選ぶ | 定着化、使用性 |
| 契約形態と支援の確認 | — | 目的は実現性の検証なので準委任契約。リードタイムなどを確認するのは、システム開発フェーズの回復力を確かめるため | 準委任契約、回復力 |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| アジャイル開発 | 短い単位で作って確かめ、変更を取り込みながら進める開発 |
| PoC | 本格導入の前に、実現可能性や効果を試して確かめること |
| MVP | 価値を検証できる最小限の機能をもつ製品 |
| 準委任契約 | 成果物ではなく、業務の遂行そのものを委託する契約 |
| プロダクトオーナー | 製品の価値と優先順位を決める責任者 |
| 重要成功要因 | 戦略の目標を達成するために、特に重要な要因 |

## 6. 思い出しクイズ
- Q1 アジャイル開発を採用した背景は → 頻繁なスコープの変更を想定する
- Q2 機械学習を業務委託した理由は → 習得の時間がない
- Q3 ベンダーを選んだ理由は → 定着化と使用性の両方が最高点だから
- Q4 準委任契約を選んだ理由は → 実現性を検証することが目的だから
- Q5 PoCのMVP試用で測定するものは → 重要成功要因の指標の値
