# 令和5年度春期 午後 問9 プロジェクトマネジメント／金融機関システムの移行プロジェクト

## 1. 覚えるキーワード3つ
- 一括移行方式：全拠点を一度に切り替える方式。営業日に業務を止めずに済む
- ステアリングコミッティの承認：本番データを使うテストのような重要な意思決定は、PMが承認を得て進める
- 移行判定基準書：本番移行してよいかを評価するための基準を書いた文書

## 2. 状況
- 金融機関のP社は、本店と全国30か所の支店(拠点)をもち、販売支援システムをオンプレミスで運用している。
- 機器やパッケージの保守期限切れを受け、システムをIaaSへ移行するプロジェクトを始めた。
- 設問は、一括移行の利点、IaaS選定の重視項目、テストの手続、初期サポート、リスク分析、移行が遅れたときの費用面の対応を問う。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| 移行方式を選ぶ | —（設問1(1)は正答率がやや低かった） | 拠点の要望(営業日の業務停止を避けたい)を本文から読み取る。一括移行なら営業日に業務の停止が不要 | 営業日、拠点 |
| 重要な意思決定をする | — | 本番データを使うテストなど重要な判断は、ステアリングコミッティの承認を得る。移行の可否は、移行判定基準書で評価する | ステアリングコミッティ、本番データ |
| 移行が遅れるリスクに備える | 費用面以外の対応策を答える(設問3(2)で散見) | 定性分析は発生確率・影響度マトリックス、重大なリスクの定量分析は感度分析。費用面の対応は、追加発生する保守費用の確保 | 費用面 |

## 4. 解答キーワード一覧

| 設問 | 問われていること | 決め手のキーワード |
|---|---|---|
| 1(1) | 一括移行の利点 | 営業日に業務の停止が不要 |
| 1(2) | セキュリティ対策の検討前に行うこと | エ(責任範囲の明確化) |
| 1(3) | IaaS選定でRFPに示す重視項目 | IaaS利用による構築期間とコスト |
| 2(1) | テスト計画の承認で行った手続 | ステアリングコミッティで本番データを用いたテストの承認を得る |
| 2(2) | 初期サポートで指示した支援 | エスカレーション対応の開発課リソースの拡充 |
| 2(3) | 移行可否の評価に必要な文書 | 移行判定基準書 |
| 3(1) a | リスクの定性的分析の手法 | オ(発生確率・影響度マトリックス) |
| 3(1) b | 重大リスクの定量的分析の手法 | ア(感度分析) |
| 3(2) | 移行遅延時の費用面の対応策 | 追加発生する保守費用の確保 |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| 一括移行 | すべての拠点を一度に新システムへ切り替える方式 |
| 段階移行 | 拠点などを分けて、順に切り替える方式 |
| ステアリングコミッティ | プロジェクトの重要事項を決める意思決定の会議体 |
| RFP | 提案依頼書。調達先に提案してほしい内容を示す |
| 発生確率・影響度マトリックス | リスクを発生確率と影響度の2軸で並べ、定性的に評価する表 |
| 感度分析 | 条件を変えたとき、結果がどう変わるかを調べる定量分析 |

## 6. 思い出しクイズ
- Q1 営業日に業務を止めずに済む移行方式は → 一括移行(方式)
- Q2 本番データを用いたテストの承認を得る相手は → ステアリングコミッティ
- Q3 移行の可否を評価するために必要な文書は → 移行判定基準書
- Q4 リスクの定性的分析で使う手法は → 発生確率・影響度マトリックス
- Q5 移行が遅れたときの、費用面の対応策は → 追加発生する保守費用の確保

※採点講評：設問1(1)は正答率がやや低かった。設問3(1)は正答率が低く、リスクの定性的・定量的分析の理解が問われた。設問3(2)は費用面以外の対応策を答えた受験者が散見された。
