# 令和7年度秋期 午後 問5 ネットワーク／クラウドサービスへの移行

## 1. 覚えるキーワード3つ
- オープンリレー防止：社外から来た社外宛てメールの中継を拒否し、踏み台にされないようにする対策
- IGW（アドレス変換）：クラウドとインターネットの出入口で、グローバルとプライベートのIPアドレスを変換する
- IPsecルータ（経路制御）：本社・営業所からクラウド内のサーバ宛ての通信を、暗号化したトンネルへ正しく送る

## 2. 状況
- A社は、DMZと社内のサーバの多くを、B社のクラウド上のA社専用環境（BCL-A）へ移す。
- 移行後もPCの操作と業務の運用は変わらない。本社とBCL-AはIPsecルータで結ぶ。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| メール中継サーバを守る | OP25Bと取り違える（採点講評で正答率が低い） | オープンリレー防止は、社外から来た社外宛てメールを中継しない処理。OP25Bは別の技術 | 社外から来た社外宛てメール |
| クラウドの出入口で通信が変換される | — | IGWを通ると宛先が変わる（200.α.β.2 → 172.20.1.14）。変換前後の値を本文の表で追う | IGW、NAT |
| 移行後も社内PCの操作は変わらない | — | PCの通信がクラウドへ届くよう、移行したサーバ宛ての経路を変える | プロキシ・メール・内部DNSサーバ |

## 4. 解答キーワード一覧

| 設問 | 問われていること | 決め手のキーワード |
|---|---|---|
| 1(1) | 営業所PCのデフォルトゲートウェイの機器 | L3SW0 |
| 1(2) | メール中継サーバで防ぐ処理 | 社外から来た社外宛てメールの中継（オープンリレー） |
| 1(3) | 表1の空欄a・b・c | Webサーバ／外部DNSサーバ／プロキシサーバ |
| 2(1) | IGW通過前後の宛先IPアドレス | 200.α.β.2 → 172.20.1.14 |
| 2(2) | IPsecルータ1が転送するパケットの送信元 | 192.168.1.0/24、172.16.128.0/20 |
| 2(3) | 経路変更が必要になる移行サーバ | プロキシ・メール・内部DNSサーバ |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| オープンリレー | 第三者のメールを無制限に中継してしまう状態 |
| OP25B | ISP外への25番ポート直送を止める技術 |
| NAT | 宛先や送信元のIPアドレスを変換する仕組み |
| IGW | クラウドとインターネットをつなぐ出入口 |
| IPsec | IP通信を暗号化してつなぐ方式 |
| デフォルトゲートウェイ | 別ネットワーク宛ての通信を最初に渡す機器 |

## 6. 思い出しクイズ
- Q1 メール中継サーバで防ぐべき処理は → 社外から送られた社外宛てメールの中継
- Q2 OP25Bはオープンリレー防止の技術か → いいえ。ISPのメールサーバを経由しない直接送信を防ぐ技術
- Q3 IGW通過後のSMTPパケットの宛先は → 172.20.1.14（メール中継サーバ）
- Q4 営業所PCのデフォルトゲートウェイの機器は → L3SW0
- Q5 社内PCの経路変更が必要になる移行サーバは → プロキシサーバ・メールサーバ・内部DNSサーバ

※採点講評：設問1(2)は正答率が低く、設問2(2)はやや低かった。
