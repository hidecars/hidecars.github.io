# 令和7年度春期 午後 問10 サービスマネジメント／容量・能力管理

## 1. ひとことで
クラウド移行を検討する製造業で、キャパシティ監視と計画の基本、インシデント時に業務影響を避ける考え方を問う。

## 2. 状況
- 製造業。オンプレミスのシステムをクラウドサービスへ移行することを検討中。
- 販売管理→生産管理のHバッチ、生産計画案を作るPバッチが遅れると、翌日の生産に影響する。
- クラウドは柔軟に増強できるが、使った分だけ利用料がかかる。

![](img/2025r07h-servicemng.svg)

## 3. 設問の狙いとキーワード

| 設問 | 問われていること | 決め手のキーワード |
|---|---|---|
| 1(1) | 製造部と営業部で協議する内容 | 前日の注文情報に基づく翌日の生産計画／バッチ遅延の業務影響と対策 |
| 1(2) | しきい値の設定方法 | 例外になるように設定 |
| 2(1) | イベントとして認識すること | Sメッセージの出力 |
| 2(2) | 増強後に行うことと理由 | 容量を元に戻す／クラウド利用料が加算される |
| 2(3) | 見積りの根拠 | 需要予測に基づくリソース使用量の見積り |
| 2(4) | 活動の名称 | キャパシティ計画 |

## 4. 解き方の型
- **型1 SLA変更に逃げない**：まず翌日の業務に支障を出さない具体策を考える。
- **型2 クラウドは「戻す」までが運用**：一時的に増やしたリソースは元に戻す。費用の視点を持つ。

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| キャパシティ計画 | 需要予測から将来のリソース量を見積もり、確保する活動 |
| キャパシティ監視 | リソースの使用状況を継続的に測る活動（補足） |
| 従量課金 | 使ったリソースの量・期間に応じた料金 |
| しきい値 | 監視で異常とみなす基準値 |
| SLA | 提供者と顧客が合意したサービスレベル |
| バッチ処理 | データをまとめて一括で処理する方式 |

## 6. 思い出しクイズ
- Q1 インシデント時、最初に協議するのはSLA変更か → いいえ、翌日の業務に支障を出さない施策
- Q2 増強したストレージを戻す理由は → クラウド利用料が加算されるから
- Q3 需要予測から将来のリソースを見積もる活動は → キャパシティ計画
- Q4 設問1(2)で、しきい値をどう設定するか → 例外になるように設定する
- Q5 監視で認識すべきイベントは → Sメッセージの出力

※採点講評：全体の正答率はやや低い。設問1(1)は「SLAの変更を協議する」という解答が散見された。
