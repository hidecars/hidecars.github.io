# 令和7年度秋期 午後 問9 プロジェクトマネジメント／ソフトウェア開発モデルが混在するプロジェクトのマネジメント

## 1. 覚えるキーワード3つ
- EVM：出来高（EV）と計画値（PV）を比べて、進捗とコストを客観的に管理する手法
- バーンダウンチャート：残作業の減り方を表すグラフ。アジャイルの進捗管理に使う
- チケット発行：追加されたタスクを1件ずつ管理に載せるための手続

## 2. 状況
- 電気機器メーカーF社が、買収したY工場の生産管理システムを開発する（担当はITシステム部開発課）。
- 一部の工程（要件定義〜実装）は、ユーザー部門と試行錯誤しながら進めるため、アジャイル開発モデルを適用する。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| 開発モデルが混在する | — | 試行錯誤が必要な工程はアジャイル、計画どおり進める工程はEVMで管理する | 試行錯誤しながら開発を進める必要がある |
| バーンダウンチャートで当日の担当を決める | 「可視化のため」（本文の期限を書いていない） | 本文の達成目標に戻る。優先度の高いタスクを3週間で終了させる | 3週間 |
| 作業が追加された | — | 追加タスクはチケットを発行して管理に載せる。残作業は残チケット数で数える | チケットを発行 |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| EVM | 出来高で進捗とコストを管理する手法 |
| EV / PV | 出来高（終えた作業の価値）／計画値 |
| バーンダウンチャート | 残作業の減り方を表すグラフ |
| イテレーション | アジャイルの短い開発の繰り返し単位 |
| リファクタリング | 外部仕様を変えずに内部構造を整理すること |
| チケット | 作業を1件ずつ管理する単位 |

## 6. 思い出しクイズ
- Q1 EVMで進捗遅れを判断するとき比べる2つは → EVとPV
- Q2 バーンダウンチャートで当日のタスクと担当を決める目的は → 優先度の高いタスクを3週間で終了させるため
- Q3 タスクが追加されたときに必要な作業は → チケットを発行する
- Q4 外部仕様を変えずにソースコードの構造を整理する作業は → リファクタリング
- Q5 アジャイルを適用した理由は → 試行錯誤しながら開発を進める必要があるから
