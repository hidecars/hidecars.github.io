# 令和7年度秋期 午後 問9 プロジェクトマネジメント／ソフトウェア開発モデルが混在するプロジェクトのマネジメント

## 1. ひとことで
ウォーターフォールとアジャイルが混在するプロジェクトで、計画とEVM・バーンダウンチャートによる進捗管理を問う。

## 2. 状況
- 電気機器メーカーF社が、買収したY工場の生産管理システムを開発する（担当はITシステム部開発課）。
- 一部の工程（要件定義〜実装）は、ユーザー部門と試行錯誤しながら進めるため、アジャイル開発モデルを適用する。

![](img/2025r07a-projmng.svg)

## 3. 設問の狙いとキーワード

| 設問 | 問われていること | 決め手のキーワード |
|---|---|---|
| 1 | アジャイルを適用した要因 | 試行錯誤しながら開発を進める必要がある |
| 2(1) | EVMで比べる指標a・b | カ EV／キ PV |
| 2(2) | バーンダウンチャートで当日のタスクと担当を決める目的 | 優先度の高いタスクを3週間で終了させる |
| 2(3) | 外部仕様を変えずに構造を整理する作業c | リファクタリング |
| 3(1) | 5日目時点の遅れ日数d | 1 |
| 3(2) | 追加タスクに対してE君が行った作業e | チケットを発行 |

## 4. 解き方の型
- **型1 目的は本文の「期限」に戻る**：「可視化のため」では足りない。本文にある「3週間で終える」という達成目標を書く。
- **型2 管理の単位をそろえる**：残作業は残チケット数で数える。タスクが増えたらチケットを発行しないと管理から漏れる。

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| EVM | 出来高で進捗とコストを管理する手法 |
| EV / PV | 出来高（終えた作業の価値）／計画値 |
| バーンダウンチャート | 残作業の減り方を表すグラフ |
| イテレーション | アジャイルの短い開発の繰り返し単位 |
| リファクタリング | 外部仕様を変えずに内部構造を整理すること |
| チケット | 作業を1件ずつ管理する単位 |

## 6. 1分セルフチェック
- Q1 EVMで進捗遅れを判断するとき比べる2つは → EVとPV
- Q2 バーンダウンチャートで当日のタスクと担当を決める目的は → 優先度の高いタスクを3週間で終了させるため
- Q3 タスクが追加されたときに必要な作業は → チケットを発行する

※採点講評：設問2(2)と設問3(2)は正答率がやや低かった。
