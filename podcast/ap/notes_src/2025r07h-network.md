# 令和7年度春期 午後 問5 ネットワーク／社内LANの障害対応

## 1. 覚えるキーワード3つ
- ARPテーブル：IPアドレスとMACアドレスの対応表。食い違いからIPアドレスの重複を見抜く
- nslookup：DNSに直接問い合わせ、名前解決が動いているかを確かめるコマンド
- SNMPトラップ：機器がしきい値超過や異常を検知し、管理者へ自発的に知らせる機能

## 2. 状況
- FWの先にDMZ（プロキシ・キャッシュDNS・ファイルサーバ）と社内LANがある。
- 障害は3つ：PCの手動IP設定による印刷障害、DNS不具合によるWeb接続障害、ファイルサーバの大量通信による帯域圧迫。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| プリンタに印刷できない | — | 設計一覧とARPテーブルを照合し、MACアドレスの不一致からIP重複を見抜く。再発防止は接続認証（IEEE 802.1X） | 表2項番3のMACアドレスがプリンタと違う |
| Webが見られない | — | 疎通（ping）だけでは足りない。名前解決そのものを確かめる（nslookup）。対策はキャッシュDNSの多重化 | キャッシュDNSサーバ、名前解決 |
| 通信が遅い | — | 原因機器を特定し、しきい値超過はSNMPトラップで知らせ、QoSで帯域を制限する | 800Mビット/秒を超える、ファイルサーバ |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| ARPテーブル | IPアドレスとMACアドレスの対応表 |
| IEEE 802.1X | LAN接続時に端末・利用者を認証する規格 |
| nslookup | DNSに問い合わせて名前解決を確認するコマンド |
| キャッシュDNSサーバ | 名前解決を代行し結果を保持するサーバ |
| SNMPトラップ | 機器が異常を検知して管理者へ自発的に通知する機能 |
| QoS | 通信の帯域や優先度を制御する技術 |

## 6. 思い出しクイズ
- Q1 プリンタにpingが通らず、ARP表のMACが違う。何が起きているか → 他機器とのIPアドレス重複
- Q2 キャッシュDNSで名前解決できるか確かめるコマンドは → nslookup
- Q3 しきい値超過をL3SWから管理者へ自発的に通知させる機能は → SNMPトラップ
- Q4 PC接続時に端末を認証する規格は → IEEE 802.1X
- Q5 帯域圧迫の対策としてQoSで制限する通信は → ファイルサーバから社内LANへのトラフィック
