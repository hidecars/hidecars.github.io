# 令和7年度春期 午後 問5 ネットワーク／社内LANの障害対応

## 1. ひとことで
社内LANの3つの障害（IP重複・DNS不具合・帯域圧迫）の原因をどう突き止め、どの技術で防ぐかを問う。

## 2. 状況
- FWの先にDMZ（プロキシ・キャッシュDNS・ファイルサーバ）と社内LANがある。
- 障害は3つ：PCの手動IP設定による印刷障害、DNS不具合によるWeb接続障害、ファイルサーバの大量通信による帯域圧迫。

![](img/2025r07h-network.svg)

## 3. 設問の狙いとキーワード

| 設問 | 問われていること | 決め手のキーワード |
|---|---|---|
| 1(1) | ARP表からIP重複と判断した理由 | 表2項番3のMACアドレスがプリンタと違う |
| 1(2) | 重複したIPアドレス | 192.168.1.21 |
| 1(3) | サブネット分割で届かなくなる通信 | ウ ブロードキャスト |
| 1(4) | PC接続時の認証規格 | エ IEEE 802.1X |
| 2(1) | 名前解決を確認するコマンド | nslookup |
| 2(2) | キャッシュDNS障害への対策 | ウ キャッシュDNSサーバを多重化する |
| 3(1) | 帯域圧迫の原因機器 | ファイルサーバ |
| 3(2) | L3SWの通知機能と条件 | SNMPトラップ／800Mビット/秒を超える |
| 3(3) | QoSで制限する通信 | ウ ファイルサーバから社内LANへ |

## 4. 解き方の型
- **型1 設定値と実測値を突き合わせる**：設計一覧（表1）とARPテーブル（表2）を照合し、不一致から原因を特定する。
- **型2 現象と標準技術を直結させる**：名前解決の確認＝nslookup、しきい値超過の通知＝SNMPトラップ、接続認証＝IEEE 802.1X。

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| ARPテーブル | IPアドレスとMACアドレスの対応表 |
| IEEE 802.1X | LAN接続時に端末・利用者を認証する規格 |
| nslookup | DNSに問い合わせて名前解決を確認するコマンド |
| キャッシュDNSサーバ | 名前解決を代行し結果を保持するサーバ |
| SNMPトラップ | 機器が異常を検知して管理者へ自発的に通知する機能 |
| QoS | 通信の帯域や優先度を制御する技術 |

## 6. 1分セルフチェック
- Q1 プリンタにpingが通らず、ARP表のMACが違う。何が起きているか → 他機器とのIPアドレス重複
- Q2 キャッシュDNSで名前解決できるか確かめるコマンドは → nslookup
- Q3 しきい値超過をL3SWから通知させる機能は → SNMPトラップ
