# 令和5年度春期 午後 問10 サービスマネジメント／クラウドサービスのサービス可用性管理

## 1. 覚えるキーワード3つ
- 計画停止時間とサービス時間の合意：SLAでは、計画停止を含めたサービスを使える時間を利用部門と合意しておく
- サービス回復までの最大時間：サービスレベル項目に追加する、障害から回復するまでにかかってよい最大の時間
- バックアップの遠隔地保管：IaaSに高可用性対策があっても、広域災害とマルウェアに備え、遠隔地保管は廃止しない

## 2. 状況
- 自動車部品製造販売会社のL社は、会計系のSaaS(Sサービス)が日中に停止し、経理部の勤務体制の変更に合わせてSLAを見直す必要が出た。
- BCP対策として、基幹系システムをクラウド事業者M社のIaaS(Iサービス)へ移す。コストを抑えつつ、災害時もサービスを続けたい。
- 設問は、可用性の指標、稼働率の計算とSLA目標の調整、管理責任の範囲、バックアップ運用の見直し、可用性のKPIを問う。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| 経理部の勤務体制が変わる | 「M社と計画停止時間の変更を協議する」(設問2(3)で散見) | 以前は営業時間外に計画停止していたが、勤務変更後は停止を考慮して勤務時間を定める。表3・表4のサービスカタログから、合意するサービスレベルを具体的に考える | 計画停止時間、勤務時間 |
| サービスレベルに項目を足す | — | 稼働率だけでなく、障害から回復するまでの最大時間も項目にする | サービス回復までの最大時間 |
| IaaSへ移してバックアップを見直す | — | 稼働系(東日本)から待機系(西日本)へ切り替える対策があっても、遠隔地保管をやめると、広域災害時のマルウェアからのデータ保護が不十分になる。可用性とセキュリティの両立が重要 | バックアップの遠隔地保管 |

## 4. 解答キーワード一覧

| 設問 | 問われていること | 決め手のキーワード |
|---|---|---|
| 1(1) | MTBFとMTRSの望ましい値 | ア(MTBFは大きく、MTRSは小さい) |
| 1(2) a | 表2の空欄 | 信頼性 |
| 2(1) b | 目標達成のための最大停止時間 | 180 |
| 2(2) | 追加するサービスレベル項目 | サービス回復までの最大時間 |
| 2(3) | 経理部と調整すべきこと | 計画停止時間を考慮して経理部の勤務時間を定めること |
| 3(1) | M社が構築・管理する範囲 | イ、エ(仮想化基盤、物理基盤) |
| 3(2) | 見直すべき点 | バックアップの遠隔地保管を廃止すること |
| 3(3) | 可用性KPIとして適切な例 | ア(M社のサービス故障数) |
| 3(4) | 継続する機能の判断基準 | 重要事業機能の支援度合い |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| MTBF | 平均故障間隔。大きいほど壊れにくい |
| MTRS | 平均サービス回復時間。小さいほど早く直る |
| SLA | サービス提供者と利用者が合意するサービスレベルの取り決め |
| IaaS | サーバなどのインフラをクラウドで借りるサービス |
| BCP | 事業継続計画。災害時にも重要な事業を続ける計画 |
| 可用性 | 必要なときにサービスを使える度合い |

## 6. 思い出しクイズ
- Q1 MTBFとMTRSは、それぞれどちらが望ましいか → MTBFは大きく、MTRSは小さく
- Q2 SLAに追加するサービスレベル項目の例は → サービス回復までの最大時間
- Q3 経理部の勤務時間を決めるとき、考慮するのは → 計画停止時間
- Q4 IaaSへ移しても廃止してはいけないものは → バックアップの遠隔地保管
- Q5 継続する機能を決める判断基準は → 重要事業機能の支援度合い

※採点講評：設問2(3)は正答率がやや低く、「M社と計画停止時間の変更を協議する」という誤った解答が散見された。設問3(2)は正答率が平均的で、可用性とセキュリティの両方を満たす対策が重要とされた。
