# 令和6年度春期 午後 問11 システム監査／支払管理システムの監査

## 1. 覚えるキーワード3つ
- 業務パッケージ選定：自社の規程に合わない標準機能を使うときは、採用を決める前の「選定」の段階で、リスク委員会の承認を得る
- 調達用支払先：調達管理システムとの連携専用に登録された支払先。誤って別の支払に使うと、データの不一致が起きる
- 減額の支払申請入力：支払予定データを直接直せないので、重複支払を防ぐため手作業で行う減額の入力

## 2. 状況
- V社は、債務管理システムから、業務パッケージを使った支払管理システムへ移行した。
- パッケージの標準機能と自社の規程のずれを、手作業のコントロールで補っている。
- 調達実績データと支払予定データが一致しない問題があり、コントロールの妥当性とデータの一貫性を監査で確かめる。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| パッケージの標準機能が規程に合わない | 開発・設計の段階で承認を得る（設問1のa・bは正答率がやや低かった） | リスクを踏まえ、採用を決める前の「業務パッケージ選定」の段階で、リスク委員会の承認を得る | 業務パッケージ選定、リスク委員会の承認 |
| データが一致しない原因を探す | 手入力ミスや通信エラーとみなす（設問4のgは正答率がやや低かった） | 連携専用の「調達用支払先」を、一般の支払申請で誤って使った可能性を読み取る | 調達用支払先 |
| 支払予定データを直せない | — | 次回の取込の前に、手作業で「減額の支払申請入力」を行い、重複支払を防ぐ | 減額の支払申請入力 |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| 保留ファイル | エラーではないが取り込めなかったデータを一時的に置くファイル |
| 調達用支払先 | 調達管理システムとの連携専用に登録した支払先 |
| 減額の支払申請入力 | 支払額を減らすために、手作業で行う申請の入力 |
| 利用者ID更新ログ | ユーザーIDの登録・変更・削除の履歴(監査証跡) |
| パスワードポリシー | パスワードの複雑さや有効期間などを定めたルール |
| 予備調査 | 本調査の前に、対象業務の現状をつかむ調査 |

## 6. 思い出しクイズ
- Q1 パッケージの標準機能が規程に合わないとき、承認を得る段階は → 業務パッケージ選定(採用を決める前)
- Q2 その承認をする主体は → リスク委員会
- Q3 重複支払を防ぐため、追加の支払申請の後に手作業で行う入力は → 減額の支払申請入力
- Q4 取込でエラーではないが保留されたデータを置くファイルは → 保留ファイル
- Q5 誤って使うと調達実績データとの不一致の原因になる支払先は → 調達用支払先

※採点講評：設問1のaとbは正答率がやや低かった。設問4のgは正答率がやや低かった。
