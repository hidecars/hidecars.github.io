# 令和6年度秋期 午後 問11 システム監査／チャットボット導入における開発計画の監査

## 1. 覚えるキーワード3つ
- テスト用データの分離：追加の機械学習のあとは、学習用とは別のテスト用データで効果を確かめ、過学習を防ぐ
- 手作業入力：機械学習だけでは足りない類義語を、手作業で入力して回答の精度を保つ機能
- 受入テスト：開発担当者任せにせず、利用部門が目標レベルに届いたかを確かめて、本番移行を判断するテスト

## 2. 状況
- W社が、AIを応用した新しいチャットボット(新CB)を導入する。現行のCBは、季節性のある製品への問合せ対応が不十分で、受入テストに顧客サービス部が参加せず混乱した。
- 新CBはPoCでの回答満足率を指標にして、開発計画を立てている。
- 監査人は、類義語DBの整備にかかるサーバの処理時間と、テスト結果のずれに対するコントロールが適切かを監査する。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| 追加の機械学習のあとに効果を確かめる | 学習に使ったデータと同じデータでテストする | 汎化性能を正しく測るため、学習用とは別のテスト用データを用意する | 学習、テスト用データ |
| 類義語を整備したい | — | AIの自動学習だけでは補えない。手作業入力ができる機能を学習機能にもたせる | 手作業入力 |
| 本番移行の可否を判断する | 「回答満足率」のような評価項目そのものだけを書く（設問1(2)のcで散見） | 評価項目ごとに、本番移行してよい水準(目標レベル)を事前に定める。遅くとも本番移行の前に効果を評価して可否を判断する（設問2(2)のgは正答率がやや低かった） | 目標レベル、本番移行 |

## 4. 解答キーワード一覧

| 設問 | 問われていること | 決め手のキーワード |
|---|---|---|
| 1(1) a | テスト用データとは別に用意するデータ | 学習 |
| 1(1) b | 類義語DB整備のための機能 | 手作業入力 |
| 1(2) c | 評価項目に対して設定する内容 | 目標レベル |
| 1(3) d | 不具合発見時に原因特定・再発防止のために行うこと | レビュー |

| 2(2) h | 過去の混乱を防ぐための計画 | 受入テスト |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| 過学習 | 学習データに合わせすぎて、新しいデータに対する精度が落ちること |
| 類義語DB | 言い換え・同義の語をまとめ、回答の精度を保つための辞書 |
| 受入テスト | 利用部門が、業務の要件を満たすかを確かめる最終のテスト |
| 性能要件 | 応答時間や処理速度に関する非機能要件 |
| PoC | 本格導入の前に、実現可能性や効果を試して確かめること |
| システム監査 | 専門性と客観性のある監査人が情報システムを点検・評価する活動 |

## 6. 思い出しクイズ
- Q1 追加の機械学習のあと、テスト用データとは別に用意するデータは → 学習(用)データ
- Q2 類義語DBを整備するための学習機能に必要な機能は → 手作業入力
- Q3 本番移行の可否判断のため、評価項目に対して事前に設定する水準は → 目標レベル
- Q4 過去の混乱を繰り返さないため、顧客サービス部が主体で行うテストは → 受入テスト
- Q5 問合せ数の偏りで、学習用データが不足しやすい製品は → 季節性のある製品

※採点講評：設問1(2)のcは、評価項目そのものを書いた解答が散見された。設問2(2)のgは正答率がやや低かった。
