# 早わかり／公開鍵暗号と共通鍵暗号（午前対策）

## 1. 覚えるキーワード3つ
- 暗号化は相手の公開鍵：機密性のために暗号化するときは、受信者の公開鍵を使う
- 署名は自分の秘密鍵：デジタル署名は、送信者の秘密鍵で文書のハッシュ値に署名する
- 鍵の数は共通鍵 n(n−1)/2、公開鍵 2n：100人なら 4,950本と200本

## 2. 状況
- 応用情報 午前（科目A）対策の「早わかり」（2026/10/30版）。午後の暗号・認証の問題の土台にもなる。
- 暗号化は「相手の公開鍵」、署名は「自分の秘密鍵」と覚える。
- 鍵の使い方は4パターン：共通鍵暗号、公開鍵暗号、デジタル署名、ハイブリッド暗号。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| BだけがAの文書を読めるようにしたい | Aの秘密鍵で暗号化する | 受信者Bの公開鍵で暗号化する。開けられるのはBの秘密鍵だけ | 暗号化＝相手の公開鍵 |
| 文書の作成者を確かめたい | 文書全体を公開鍵で暗号化する | 送信者Aの秘密鍵でハッシュ値に署名し、Aの公開鍵で検証する | 署名するのは文書ではなくハッシュ値 |
| TLSで本文を共通鍵で暗号化する理由 | 公開鍵暗号のほうが安全だから | 公開鍵暗号は遅いので、共通鍵の受け渡しだけに使う（ハイブリッド暗号） | 処理が速い |
| 公開鍵が本人のものか確かめたい | 公開鍵をそのまま信用する | 認証局（CA）が発行するデジタル証明書で保証する（PKI） | CAの秘密鍵で署名、CAの公開鍵で検証 |

## 4. 解答キーワード一覧

| 設問 | 問われていること | 決め手のキーワード |
|---|---|---|
| Q1 | BだけがAの文書を読めるよう、Aが使う鍵 | Bの公開鍵 |
| Q2 | デジタル署名を作る鍵と署名する対象 | Aの秘密鍵／文書のハッシュ値 |
| Q3 | 50人が共通鍵暗号で相互に通信するときの鍵の数 | 1,225本（50×49÷2） |
| Q4 | TLSで本文を共通鍵で暗号化する理由 | 処理が速いから |
| Q5 | 公開鍵が本人のものだと保証する仕組み | PKI（認証局CAが発行するデジタル証明書） |
| Q6 | デジタル署名で実現できない要素 | 機密性 |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| 共通鍵暗号 | 暗号化と復号で同じ鍵を使う方式。速いが、鍵を安全に渡す方法が課題（鍵配送問題）。例：AES（DES・3DESは旧式） |
| 公開鍵暗号 | 公開鍵と秘密鍵のペアを使う方式。公開鍵は配ってよいので鍵配送問題がないが、遅い。例：RSA、楕円曲線暗号（ECC） |
| デジタル署名 | 送信者の秘密鍵でハッシュ値に署名する方式。完全性・本人確認・否認防止はできるが、機密性はない |
| ハイブリッド暗号 | 鍵の受け渡しだけ公開鍵、本文は速い共通鍵。例：TLS、S/MIME |
| PKI／CA | 認証局（CA）が「この公開鍵はBのもの」と署名した証明書で、公開鍵の持ち主を保証する仕組み。失効の確認はCRL（失効リスト）またはOCSP |
| 鍵の数 | 共通鍵は2人ごとに1本でn(n−1)/2。公開鍵は1人2本（公開＋秘密）で2n |

## 6. 思い出しクイズ
- Q1 BだけがAの文書を読めるよう、Aが使う鍵は → Bの公開鍵
- Q2 デジタル署名を作る鍵と、署名する対象は → Aの秘密鍵／文書のハッシュ値
- Q3 50人が共通鍵暗号で相互に通信するときの鍵の数は → 1,225本（公開鍵方式なら100本）
- Q4 TLSで本文を共通鍵で暗号化する理由は → 処理が速いから
- Q5 公開鍵が本人のものだと保証する仕組みは → PKI（認証局CAが発行するデジタル証明書）
- Q6 デジタル署名で実現できない要素は → 機密性

※ひっかけ：「秘密鍵で暗号化」とあったら署名のこと（本人確認）。公開鍵方式の鍵の数を n と答えるのは誤りで、正しくは 2n。
