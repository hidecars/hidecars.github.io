# 早わかり 暗号①：共通鍵・公開鍵・デジタル署名・ハイブリッド暗号

## 1. 覚えるキーワード3つ

- 暗号化は相手の公開鍵：機密性のために暗号化するときは、受信者の公開鍵を使う
- 署名は自分の秘密鍵：デジタル署名は、送信者の秘密鍵で文書のハッシュ値に署名する
- 本文は共通鍵、鍵の受け渡しは公開鍵：これがハイブリッド暗号（TLSなど）

## 2. 状況

- 応用情報 午前（科目A）対策の「早わかり」（2026/10/30版）。午後の暗号・認証の問題の土台にもなる。
- 暗号化は「相手の公開鍵」、署名は「自分の秘密鍵」と覚える。
- 前編では、鍵の使い方4パターンを、図で「誰の何の鍵を使うか」を中心に確かめる。鍵の数の計算とPKIは後編。

## 3. 4つのパターン

### 1. 共通鍵暗号

暗号化と復号で、同じ鍵を使う方式。処理が速い。課題は、その鍵を相手に安全に渡す方法（鍵配送問題）。

![共通鍵暗号：同じ鍵で暗号化と復号](img/extra-pubkey-1.svg)

- 代表的な方式：AES（DES・3DESは旧式）。
- 速いので、大きなデータの暗号化に向く。
- 弱点：通信相手ごとに別の鍵が必要になり、鍵の数が増える。鍵を安全に渡す方法も別に要る。

### 2. 公開鍵暗号

公開鍵と秘密鍵のペアを使う方式。公開鍵は配ってよいので、鍵配送問題がない。処理は遅い。

![公開鍵暗号：相手の公開鍵で暗号化し、相手の秘密鍵で復号](img/extra-pubkey-2.svg)

- 暗号化は「受信者の公開鍵」で行う。開けられるのは、受信者の秘密鍵だけ。
- 代表的な方式：RSA、楕円曲線暗号（ECC）。
- 公開鍵で暗号化した文書は、同じ公開鍵では開けない。復号には対になる秘密鍵が要る。
- 誤り：「Aの秘密鍵で暗号化する」「Bの秘密鍵で暗号化する」は暗号化の答えにならない。BだけがAの文書を読めるようにするには、Bの公開鍵で暗号化する。

### 3. デジタル署名

文書の作成者を確かめ、改ざんされていないことを確かめる方式。署名を作るのは、送信者の秘密鍵。検証するのは、送信者の公開鍵。

![デジタル署名：Aの秘密鍵でハッシュ値に署名し、Aの公開鍵で検証](img/extra-pubkey-3.svg)

- 署名するのは文書そのものではなく、文書のハッシュ値。ハッシュ値は文書が1文字でも変われば変わる短い値で、速く署名できる。
- 受信者は、受け取った文書から自分でハッシュ値を作り、署名を送信者の公開鍵で戻したハッシュ値と比べる。一致すれば、本人が作り、改ざんされていない。
- できること：本人確認（なりすまし防止）、完全性（改ざん検知）、否認防止。
- できないこと：機密性。文書は暗号化されていないので、誰でも読める。
- 覚え方：「秘密鍵で暗号化」とあったら署名のこと（本人確認）。

### 4. ハイブリッド暗号

公開鍵暗号は遅く、共通鍵暗号は鍵の受け渡しが課題。両方の良いところを組み合わせるのがハイブリッド暗号。

![ハイブリッド暗号：本文は共通鍵、共通鍵は公開鍵で受け渡す](img/extra-pubkey-4.svg)

- 送信者が一時的な共通鍵を作り、本文をその共通鍵で暗号化する（速い）。
- その共通鍵を、受信者の公開鍵で暗号化して送る（鍵の受け渡しだけ公開鍵）。
- 受信者は、自分の秘密鍵で共通鍵を取り出し、その共通鍵で本文を復号する。
- 例：TLS、S/MIME。「TLSで本文を共通鍵で暗号化する理由は処理が速いから」と聞かれる。

## 4. 4つの比較

| 方式 | 使う鍵 | 目的 | 速さ | 弱点・特徴 |
|---|---|---|---|---|
| 共通鍵暗号 | 同じ鍵1本 | 機密性 | 速い | 鍵の受け渡しが課題 |
| 公開鍵暗号 | 受信者の公開鍵で暗号化／受信者の秘密鍵で復号 | 機密性 | 遅い | 鍵の受け渡しは不要 |
| デジタル署名 | 送信者の秘密鍵で署名／送信者の公開鍵で検証 | 本人確認・改ざん検知 | ハッシュ値に署名するので速い | 機密性はない |
| ハイブリッド暗号 | 本文は共通鍵／共通鍵は公開鍵で渡す | 機密性＋速さ | 速い | TLS・S/MIMEで使う |

## 5. 思い出しクイズ

- Q1 BだけがAの文書を読めるよう、Aが使う鍵は → Bの公開鍵
- Q2 Bの公開鍵で暗号化した文書を開けるのは → Bの秘密鍵だけ
- Q3 デジタル署名を作る鍵と、署名する対象は → Aの秘密鍵／文書のハッシュ値
- Q4 デジタル署名を検証する鍵は → Aの公開鍵
- Q5 デジタル署名でできないことは → 機密性（文書は暗号化されない）
- Q6 共通鍵暗号の最大の課題は → 鍵を安全に渡すこと（鍵配送問題）
- Q7 TLSで本文を共通鍵で暗号化する理由は → 処理が速いから
- Q8 ハイブリッド暗号で、公開鍵暗号を使うのは何のためか → 共通鍵の受け渡しのため
- Q9 「秘密鍵で暗号化」と書かれていたら何のこと → デジタル署名（本人確認）
