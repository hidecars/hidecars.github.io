# 令和4年度秋期 午後 問9 プロジェクトマネジメント／プロジェクトのリスクマネジメント

## 1. 覚えるキーワード3つ
- RBS：リスクを体系的に分類する構造。リスクカテゴリを検討するのに有効
- 有識者の参画：過去に経験のない技術を使うときは、ブレーンストーミングや過去の一覧だけでは足りない。知見のある人を参画させる
- デシジョンツリーと期待値：対応策ごとに、追加コストと遅延の追加コストの最大値に発生確率を掛けて足し、期待値で比べる

## 2. 状況
- 機械部品を製造販売するK社が、AI機能をもつ新生産計画システムを、ベンダーのT社と開発している。
- 要件定義のクリティカルパスであるAI処理時間の検証で、10月にT社への問合せが増え、遅延するリスクが出た。
- 契約変更や、M君の講習の受講などの対策案をデシジョンツリーで評価し、追加コストを最小にする。リスクの特定は継続する。

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| RBS | リスクを階層的に分類した構造 |
| デシジョンツリー | 選択肢と結果を枝で表し、期待値で比べる手法 |
| 期待値 | 各結果の値に発生確率を掛けて足した値 |
| クリティカルパス | 遅れると全体が遅れる、最も長い作業の経路 |
| 特性要因図 | 原因と結果の関係を魚の骨のように整理する図 |
| ブレーンストーミング | 自由に意見を出し合って、案を集める方法 |

## 6. 思い出しクイズ
- Q1 リスクを体系的に分類する構造は → RBS
- Q2 AIのリスクを特定できなかった理由は → AIに知見のあるT社が参画していないから
- Q3 対応策を比べるために使う手法は → デシジョンツリー
- Q4 期待値が最小の対応は、何番か → 項番2(期待値80)
- Q5 リスク管理に追加すべき活動は → 進捗に従ってリスクの特定を継続して行う

※採点講評：設問1は正答率が低く、RBSの理解が問われた。設問3(2)は正答率がやや低く、計算式は複雑ではないので落ち着いて計算することが求められた。
