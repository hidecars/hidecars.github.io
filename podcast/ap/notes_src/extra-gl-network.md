## 2. 核心：用語ごとの判断ルール

### 1. TCPとUDP

どちらもトランスポート層のプロトコルで、「どのアプリケーションに渡すか」をポート番号で区別する。TCPはコネクション型で、信頼性を確保する。UDPはコネクションレスで、確認応答も順序制御もしない。

![TCPとUDPの違い（コネクションの作り方と信頼性）](img/extra-gl-network-1.svg)

- TCPのヘッダーにあって、UDPのヘッダーにないもの：シーケンス番号、確認応答番号、ウィンドウサイズ。（R3秋・R7秋に同じ問い）
- 両方にあるもの：送信元・宛先ポート番号、チェックサム。
- 補足：TCPは通信の前に、SYN→SYN+ACK→ACKの3段階のやり取り（3ウェイハンドシェイク）でコネクションを作る。確認応答が返ってこなければ再送する。この「確認」と「順序の管理」のために、シーケンス番号と確認応答番号がある。
- 補足：ウィンドウサイズは「確認応答を待たずに続けて送ってよい量」で、受信側の余裕に合わせて送る速さを調整する。
- UDPを使う例：DNSの問合せ、DHCP、SNMP、NTP、音声通話（VoIP）。少しの欠落より、遅れないことが大事な用途に向く。
- データ転送用（20番）と制御用（21番）で別のポートを使うのはFTP。
- 誤り：「ポート番号はTCPにしかない」は誤り。UDPにもある。
- 誤り：「UDPは確認応答で信頼性を確保する」は誤り。信頼性の確保はTCPの役割。

| ヘッダーの項目 | TCP | UDP |
|---|---|---|
| 送信元ポート番号・宛先ポート番号 | ある | ある |
| チェックサム | ある | ある |
| シーケンス番号 | ある | ない |
| 確認応答番号 | ある | ない |
| ウィンドウサイズ | ある | ない |

### 2. サブネットとCIDRの計算

CIDRは、クラスA〜Cの区分にとらわれず、ネットワーク部の長さを「/ビット数」で自由に決める方式。IPアドレスは32ビットで、先頭から「/ビット数」までがネットワーク部、残りがホスト部になる。

- ネットワークアドレス：IPアドレスとサブネットマスクのAND（両方が1のビットだけ1）。ホスト部がすべて0になる。
- ブロードキャストアドレス：ホスト部のビットをすべて1にしたもの。
- 割り当てられるホスト数：2のホスト部ビット数乗 −2（ネットワークアドレスとブロードキャストアドレスを除く）。
- 誤り：ホスト数を「2のn乗」と答えるのは誤り。2を引く。
- 近道：マスクが途中のオクテットにかかるときは、「区切りの大きさ」で考える。区切りの大きさは、256からそのオクテットのマスクの値を引いたもの。/29なら256−248＝8。アドレスを区切りの倍数に切り捨てるとネットワークアドレス、区切りの終わりがブロードキャストアドレス。

| 表記 | サブネットマスク | ホスト部のビット数 | 使えるホスト数 | 区切りの大きさ |
|---|---|---|---|---|
| /24 | 255.255.255.0 | 8 | 254 | 256 |
| /25 | 255.255.255.128 | 7 | 126 | 128 |
| /26 | 255.255.255.192 | 6 | 62 | 64 |
| /27 | 255.255.255.224 | 5 | 30 | 32 |
| /28 | 255.255.255.240 | 4 | 14 | 16 |
| /29 | 255.255.255.248 | 3 | 6 | 8 |
| /30 | 255.255.255.252 | 2 | 2 | 4 |

### 3. 伝送時間と回線速度の計算

伝送時間＝送るデータ量（ビット）÷（回線速度×伝送効率）。

![伝送時間の計算手順](img/extra-gl-network-2.svg)

- バイトはビットに直す。1バイト＝8ビット。
- 伝送効率が示されたら、回線速度に掛けてから割る。
- 補足：回線速度の「M」は、断りがなければ100万（10の6乗）として計算する。100Mビット/秒は1億ビット/秒。
- 誤り：バイトをビットに直し忘れて、答えが8分の1になる誤り。
- 逆向きの問い（制限時間内に送りたい）は、データ量（ビット）÷時間で、必要な速度が出る。

### 4. ビット誤り率の計算

ビット誤り率は、送ったビットのうち誤るビットの割合。

![ビット誤り率から誤りパケット数を出す手順](img/extra-gl-network-3.svg)

- 1パケットが誤る確率 ≒ 1パケットのビット数 × ビット誤り率（誤り率が十分小さいとき）。
- 誤りを含むパケット数 ≒ パケット数 × 1パケットが誤る確率。
- 誤り：%の換算ミス。0.0001%＝0.000001（100万分の1）。
- 補足：％を小数にするときは、100で割る。0.0001％を100で割ると0.000001。

## 3. 数値例（手順つき）

### 例1：192.168.16.40/29（R4秋と同じ形）

第4オクテットの40を2進数にすると00101000。/29のマスクは第4オクテットが11111000（248）。

| 項目 | 第4オクテットの2進数 | 10進数 |
|---|---|---|
| IPアドレス | 0 0 1 0 1 0 0 0 | 40 |
| マスク（/29） | 1 1 1 1 1 0 0 0 | 248 |
| AND＝ネットワークアドレス | 0 0 1 0 1 0 0 0 | 40 |
| ホスト部を全部1＝ブロードキャスト | 0 0 1 0 1 1 1 1 | 47 |

使えるホストは.41〜.46の6個（2の3乗−2）。

### 例2：172.30.123.45、マスク255.255.252.0（R5秋と同じ形）

マスクは/22。ホスト部は10ビット。第3オクテットにマスクがかかる（252）ので、区切りの大きさは256−252＝4。

| 項目 | 第3オクテットの2進数 | 10進数 |
|---|---|---|
| IPアドレス | 0 1 1 1 1 0 1 1 | 123 |
| マスク | 1 1 1 1 1 1 0 0 | 252 |
| AND | 0 1 1 1 1 0 0 0 | 120 |

ネットワークアドレスは172.30.120.0。ブロードキャストは172.30.123.255。使えるホストは2の10乗−2＝1,022個。

### 例3：伝送時間（R5秋と同じ形）

100Mビット/秒のLANで、1,000バイトの電文を1,000件送る。1,000×1,000×8＝800万ビット。800万÷1億＝0.08秒。

### 例4：必要な回線速度（R6秋と同じ形）

1Mバイトを5秒以内に送る。1,000,000×8＝800万ビット。800万÷5秒＝160万ビット/秒。1.6Mビット/秒以上の回線を選ぶ。

### 例5：ビット誤り率（R6春とR7秋に同じ数値で出題）

ビット誤り率0.0001%、1,500バイトのパケットを10,000個送る。

1. 1パケットは1,500×8＝12,000ビット。
2. 0.0001%は100万分の1。
3. 1パケットが誤る確率は12,000÷100万＝0.012。
4. 誤りを含むパケットは10,000×0.012＝約120個。

## 4. 思い出しクイズ

- Q1 UDPのヘッダーになく、TCPのヘッダーにある情報は → シーケンス番号（確認応答番号、ウィンドウサイズ）

- Q4 TCPがコネクションを作る3段階のやり取りは → 3ウェイハンドシェイク（SYN、SYN+ACK、ACK）
- Q5 /29で使えるホストアドレスの数は → 6個（8−2）
- Q6 192.168.16.40/29のブロードキャストアドレスは → 192.168.16.47
- Q7 172.30.123.45、マスク255.255.252.0のネットワークアドレスは → 172.30.120.0
- Q8 マスク255.255.252.0の区切りの大きさは → 4（256−252）
- Q9 100Mビット/秒で8Mバイトを送る時間は（効率100%） → 0.64秒（6,400万÷1億）
- Q10 1Mバイトを5秒以内に送るのに必要な最低速度は → 1.6Mビット/秒
- Q11 伝送時間の計算でまずすることは → バイトをビットに直す（×8）
- Q12 0.0001%を小数で表すと → 0.000001（100万分の1）
