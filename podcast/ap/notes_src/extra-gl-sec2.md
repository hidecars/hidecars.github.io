## 2. 核心：用語ごとの判断ルール

### 1. CSIRT・PSIRT・JVN・CVE・CVSS

脆弱性とインシデントに対応する組織と、脆弱性情報の共通の呼び方・評価方法。

- CSIRT：組織内で発生したセキュリティインシデントに対応するチーム。
- PSIRT：自社が開発・販売する製品の脆弱性に対応するチーム。「自社製品の脆弱性」と出たらPSIRT。
- JVN：日本で使われているソフトウェア製品の脆弱性情報と対策を公開するポータルサイト。JPCERT/CCとIPAが共同で運営する。
- CVE：個々の脆弱性に付ける一意の識別番号（CVE-年-連番）。
- CVSS：脆弱性の深刻度を数値で評価する方法。過去問では「基本評価基準・現状評価基準・環境評価基準の三つ」で出題された（CVSS v3の区分）。
- 誤り：CVEとCVSSの取り違え。CVEは「識別番号」、CVSSは「深刻度の評価」。

### 2. サイドチャネル攻撃・耐タンパ性・TPM・セキュアブート

機器の物理的な性質を突く攻撃と、それを防ぐハードウェア側の対策。

- サイドチャネル攻撃：暗号処理中の処理時間・消費電力・電磁波などを測定し、秘密鍵などの内部情報を推測する。
- 耐タンパ性：内部の情報を不正に読み出されにくい性質。例：ICカードを分解しようとすると内部の情報が消える仕組み。
- TPM：鍵の生成・保管と暗号処理を行うセキュリティチップ。鍵をチップの外に出さない。
- セキュアブート：起動時にOSのローダーなどのデジタル署名を検証し、改ざんされたソフトウェアを起動させない。
- 誤り：「ネットワークを盗聴して鍵を得る」はサイドチャネル攻撃ではない。サイドチャネルは「処理時間・消費電力・電磁波」の測定。

### 3. JIS Q 27000の情報セキュリティの特性

JIS Q 27000:2019の情報セキュリティの定義では、機密性・完全性・可用性の3要素に加えて、真正性・責任追跡性・否認防止・信頼性の4つの特性が挙げられている。

- 機密性：認可されていない個人・エンティティ・プロセスに、情報を使用させず、開示しない特性。
- 完全性：正確さ及び完全さの特性。
- 可用性：認可されたエンティティが要求したときに、アクセス及び使用が可能である特性。
- 真正性：エンティティは、それが主張するとおりのものであるという特性。
- 信頼性：意図する行動と結果が一貫しているという特性。
- 否認防止：主張された事象又は処置の発生、及びそれを引き起こしたエンティティを証明する能力。
- 責任追跡性：ある活動を誰が行ったかを、後から追跡できること。
- 誤り：真正性と信頼性の取り違え。「主張するとおり」は真正性、「意図する行動と結果が一貫」は信頼性。

### 4. WAFとWebアプリケーションへの攻撃・ファジング

WAFは、Webアプリケーションへの通信の中身を検査し、攻撃を遮断する仕組み。

- WAFが防げる攻撃：SQLインジェクション、クロスサイトスクリプティング（XSS）など、HTTPの中身に攻撃が含まれるもの。
- ファイアウォールはIPアドレスとポート番号で通信を制御する。HTTPの中身は見ない。
- SQLインジェクション：入力欄にSQL文の一部を入れて、データベースを不正に操作する。対策はプレースホルダ（バインド機構）。
- XSS：Webページに悪意のあるスクリプトを埋め込み、閲覧者のブラウザで実行させる。対策は出力時のエスケープ処理。
- ファジング：予期しないデータ（ファズ）を大量に入力して、ソフトウェアの脆弱性を見つける検査手法。
- 誤り：「WAFはIPアドレスとポート番号だけで通信を制御する」は誤り。それはファイアウォール。WAFはHTTPの中身を検査する。

### 5. SBOMとCSPM（R6秋・R7秋に連続出題）

ソフトウェアとクラウドの「中身と設定」を把握・管理するための新しい仕組み。

- SBOM（ソフトウェア部品表）：ソフトウェアを構成するコンポーネント（OSSを含む）の名前・バージョン・依存関係・ライセンスの一覧。新しい脆弱性が公表されたとき、影響を受ける製品をすぐ特定できる。
- CSPM：クラウドサービスの設定を継続的に点検し、設定ミスや設定の不備を検出して是正する仕組み。
- 似た用語：CASBは、社員のクラウドサービス利用を可視化・制御する仕組み。
- 誤り：SBOMとCSPMの取り違え。部品の一覧はSBOM、クラウドの設定点検はCSPM。

## 3. 思い出しクイズ

- Q1 自社製品の脆弱性に対応する社内機能は → PSIRT
- Q2 脆弱性に付ける一意の識別番号は → CVE
- Q3 基本・現状・環境の三つの基準で深刻度を評価するのは → CVSS
- Q4 消費電力や処理時間から秘密鍵を推測する攻撃は → サイドチャネル攻撃
- Q5 起動時に署名を検証し、改ざんされたソフトを起動させない仕組みは → セキュアブート
- Q6 鍵を外に出さずに保管・暗号処理するチップは → TPM
- Q7 「認可されていない者に情報を開示しない特性」は → 機密性
- Q8 「エンティティが主張するとおりのものである特性」は → 真正性
- Q9 「意図する行動と結果が一貫している特性」は → 信頼性
- Q10 WAFによる防御が有効な攻撃の例を2つ → SQLインジェクション、クロスサイトスクリプティング
- Q11 予期しないデータを大量に入力して脆弱性を見つける手法は → ファジング
- Q12 SQLインジェクションの対策は → プレースホルダ（バインド機構）
- Q13 ソフトウェアの構成部品を一覧にしたものは → SBOM
- Q14 クラウドの設定ミスを継続的に検出する仕組みは → CSPM
- Q15 脆弱性公表時にSBOMが役立つ理由は → 影響を受ける製品をすぐ特定できるから
