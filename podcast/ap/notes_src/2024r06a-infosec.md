# 令和6年度秋期 午後 問1 情報セキュリティ／Webサイトのセキュリティ

## 1. 覚えるキーワード3つ
- 多層防御：一つの対策が破られても、ほかの対策で攻撃を防ぐ設計の考え方
- プレースホルダ：SQLインジェクションを防ぐため、SQL文のひな形に入力値を後から当てはめる仕組み
- ペッパー：会員テーブルの外の安全な場所に置き、全会員のパスワードに共通で付け足す文字列

## 2. 状況
- ECサイトのペネトレーションテストで、SQLインジェクションの脆弱性が見つかり、会員テーブル(パスワードのハッシュ値)が漏えいするおそれが分かった。
- ハッシュ値が漏えいしたときの影響と、ハッシュ値からパスワードを割り出す攻撃(レインボーテーブル攻撃など)への対策を検討する。
- プレースホルダに加え、ソルト・ペッパー・ストレッチング・パスワード長の拡大を組み合わせた多層防御を考える。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| ハッシュ値が漏えいした | 情報セキュリティの3要素ではない語を答える（設問2で散見） | ハッシュ値からパスワードの割出しは難しい。ただし漏えいそのものは「機密性」が侵害された状態 | ハッシュ値、機密性 |
| SQLインジェクションを防ぐ | — | 入力値をSQL文へ直接埋め込まず、プレースホルダで当てはめる | プレースホルダ、バインド |
| ハッシュ値からパスワードを割り出されたくない | — | ペッパーは会員テーブルの外に置く。テーブルを盗まれただけではペッパーを得られず、割出しが難しくなる | 会員テーブルの窃取だけではペッパーを得ることができない |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| ハッシュ関数 | データを、元に戻せない固定長の値(ハッシュ値)に変換する一方向の関数 |
| レインボーテーブル攻撃 | 平文とハッシュ値の対応表で、ハッシュ値から元のパスワードを割り出す攻撃 |
| ソルト | 会員ごとに付け足し、同じパスワードが同じハッシュ値にならないようにする文字列(DB内) |
| ペッパー | 全会員共通で付け足す文字列。DBの外の安全な場所に置く |
| ストレッチング | ハッシュ化を何度も繰り返し、総当たりにかかる時間を増やす手法 |
| 多層防御 | 複数の対策を重ね、一つが破られても被害を防ぐ考え方 |

## 6. 思い出しクイズ
- Q1 パスワードをハッシュ値で保存する利点は → ハッシュ値からパスワードの割出しが難しいこと
- Q2 入力値をひな形に当てはめ、SQL文の構造が変わらないようにする対策は → プレースホルダ
- Q3 会員テーブルが盗まれても割出しを難しくする、DBの外に置く共通の文字列は → ペッパー
- Q4 ハッシュ値の漏えいで侵害される、情報セキュリティの要素は → 機密性
- Q5 仮に一つの対策が破られても、ほかの対策で防ぐ考え方は → 多層防御

※採点講評：設問1・設問2は正答率がやや高かった。設問2では、情報セキュリティの3要素ではない誤った解答が散見された。
