# 令和6年度秋期 午後 問5 ネットワーク／セキュアWebゲートウェイサービスの導入

## 1. 覚えるキーワード3つ
- NAPT：プライベートIPアドレスとポート番号の組を、グローバルIPアドレスとポート番号の組に相互変換する技術
- URL：Webサイトの位置を示す識別子。接続先IPアドレスだけでなく、URLの内容でも危険なサイトを判別する
- サンドボックス：受け取ったプログラムを隔離された領域で動かし、悪意がないかを確かめる機能

## 2. 状況
- E社が自社のプロキシサーバをやめ、クラウド型のセキュアWebゲートウェイ(サービスZ)へ移行する。
- PCからのWeb閲覧は、ソフトCを経由してサービスZ(ip8)へHTTPS(ポート443)で送る構成に変わる。
- E社ルータのNAPTによる送信元IPアドレスの制限は維持し、業務サーバへの直接アクセスも残す。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| SaaSが送信元IPアドレスでアクセスを制限している | —（設問1(2)は正答率がやや低かった） | ルータのNAPTで、内部のPCは外側のIPアドレス(ip1)にまとめて変換される。相手からはip1として見える | 送信元IPアドレスでアクセス制限 |
| 危険なWebサイトを見分ける | — | 接続先IPアドレスに加えて、URLの内容を確認して判定する（設問2(1)は正答率がやや低かった） | 接続先IPアドレス、URL |
| プロキシをやめてFWの許可を変える | — | PCからサービスZ(ip8)宛てのHTTPS(443)を許可する。業務サーバは直接通信のままにする | ip8、443、業務サーバ |

## 4. 解答キーワード一覧

| 設問 | 問われていること | 決め手のキーワード |
|---|---|---|
| 1(1) | 変換する技術(a) | NAPT |
| 1(2) | SaaSから見た送信元IPアドレス | ip1 |
| 2(1) | 危険なサイトの判別に使うもの(b) | URL |
| 2(2) | 隔離領域でプログラムを動かし確認する機能 | ウ(サンドボックス) |
| 3(1) | FWで許可する宛先IPアドレス(c) | ip8 |
| 3(2) | 直接HTTP通信させる接続先(d) | 業務サーバ |
| 4 | 導入前のFWルールの送信元(e)／TCPポート(f) | プロキシサーバ または ip3／443 |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| NAPT | プライベートIPとポートを、グローバルIPとポートに相互変換する技術 |
| サンドボックス | 隔離された領域でプログラムを動かして安全を確かめる機能 |
| プロキシサーバ | クライアントの代わりにWebアクセスを中継する機器 |
| ファイアウォール(FW) | IPアドレスやポート番号で通信の通過・遮断を制御する装置 |
| HTTPS | HTTPをTLSで暗号化して送受信するプロトコル |
| URL | Web上の情報の場所を示す識別子 |

## 6. 思い出しクイズ
- Q1 ルータがプライベートIPとポート番号を変換する技術は → NAPT
- Q2 SaaSから見た、E社の送信元IPアドレスは → ip1
- Q3 危険なWebサイトの判別で、接続先IPアドレスのほかに確認する重要な情報は → URL
- Q4 サービスZの導入後、FWで許可する宛先IPアドレスは → ip8
- Q5 サービスZとの通信で使うTCPのポート番号は → 443

※採点講評：設問1(2)と設問2(1)は正答率がやや低かった。全体の正答率は高かった。
