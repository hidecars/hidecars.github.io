## 2. 核心：用語ごとの判断ルール

### 1. 認証方式（チャレンジレスポンス・SAML・リスクベース認証）

利用者が本人であることを確かめる方式。午前では「パスワードを送らない方式」「シングルサインオン」「状況に応じて追加認証する方式」が出る。

![SAMLによるシングルサインオン](img/extra-gl-sec1b-1.svg)

- チャレンジレスポンス認証：サーバが毎回違う乱数（チャレンジ）を送り、利用者側はパスワードと乱数から計算した値（レスポンス）を返す。パスワードそのものはネットワークに流れない。
- SAML：認証を行うIdP（アイデンティティプロバイダ）が認証結果（アサーション）を発行し、クラウドサービス側（SP）はそれを信頼してログインさせる。シングルサインオンを実現する。
- リスクベース認証：いつもと違う端末・場所・時間からのアクセスのときだけ、追加の認証を求める。
- 3Dセキュア2.0：クレジットカードのネット決済の本人認証。リスクベース認証で、危険度が高い取引だけ追加の認証を求める。
- 補足：チャレンジが毎回違うので、通信を盗み見て同じ応答を送り直しても（リプレイ攻撃）通らない。
- 誤り：「SAMLではクラウドサービス側が利用者のパスワードを保管して照合する」は誤り。認証するのはIdP。

### 2. パスワード攻撃（4種類の区別）

パスワードを推測・入手して不正にログインする攻撃。午前では4種類の区別が出る。「何を固定し、何を変えるか」で見分ける。

- ブルートフォース攻撃：1つのIDに対して、パスワードを総当たりで試す。
- リバースブルートフォース攻撃：パスワードを1つに固定し、IDを次々に変えて試す。1つのIDへの失敗回数が増えないので、アカウントロックを回避できる。
- パスワードリスト攻撃：他のサイトから漏えいしたIDとパスワードの組を使ってログインを試す。パスワードの使い回しが狙われる。
- レインボーテーブル攻撃：パスワードとハッシュ値の対応を事前に計算した表を使い、ハッシュ値から元のパスワードを割り出す。対策は「ソルト」（パスワードごとに違う値を加えてからハッシュ化する）。
- 午後での問われ方：「ロックアウトで防げない理由」は、同一のIDで2回以上ログインを試行しないから（R7春 午後問1）。
- 誤り：リバースブルートフォースとパスワードリスト攻撃の取り違え。「漏えいしたIDとパスワードの組」が出たらパスワードリスト攻撃。

| 攻撃 | 固定するもの | 変えるもの | 効かない／効く対策 |
|---|---|---|---|
| ブルートフォース | ID | パスワード | アカウントロックが効く |
| リバースブルートフォース | パスワード | ID | アカウントロックが効かない |
| パスワードリスト | （漏えいしたIDとパスワードの組） | 試すサイト | 使い回しをやめる・多要素認証 |
| レインボーテーブル | ハッシュ値 | 事前計算の表 | ソルト |

### 3. ゼロトラスト

社内・社外を区別せず、すべてのアクセスを信頼せずに毎回検証する考え方。

![境界防御とゼロトラストの違い](img/extra-gl-sec1b-2.svg)

- 境界防御（FWの内側は安全）の反対。利用者・端末・通信を、その都度、認証・認可し、ログで監視する。
- 午後での問われ方：「境界防御だけでは不十分な理由」。内部に侵入された後の横展開を防げない、と書く。
- 補足：境界防御は「城壁の内側は信じる」考え方。一度内側に入られると、他のサーバへ広がっても止められない。ゼロトラストは、内側でも毎回確かめる。
- 出題実績：R7秋 午後問1（空欄a：境界防御）と対で覚える。

### 4. IDaaS／SSO

IDaaSは、クラウドで認証・ID管理を提供するサービス。SSOは、1回の認証で複数のサービスを使える仕組み。

- 認証をIDaaSに集約すると、退職者のID停止や多要素認証の適用を1か所で管理できる。
- 午後での問われ方：「ID管理を集約する利点」として、アカウント削除漏れの防止、統一した認証強化を書く。
- 補足：SSOを実現する仕組みの一つが、前のテーマのSAML。IDaaSがIdPの役割を担うことが多い。

### 5. パスキー（FIDO2）

パスワードの代わりに、端末内の秘密鍵と生体認証などで本人確認する方式。FIDO2／WebAuthnという規格に基づく。

![パスキーによるログインの流れ](img/extra-gl-sec1b-3.svg)

- サーバには公開鍵だけを登録する。パスワードを送らないので、フィッシングや使い回しの被害を受けにくい。
- 午後での問われ方：「パスワード漏えい・リスト型攻撃への対策」として書ける。秘密鍵が端末から出ない点が要点。
- 補足：仕組みは、デジタル署名と同じ。サーバが送る乱数に、端末の秘密鍵で署名して返し、サーバが登録済みの公開鍵で検証する。本人確認（生体認証など）は、端末の中の秘密鍵を使うための鍵あけとして行う。

## 3. 思い出しクイズ

- Q1 パスワードそのものをネットワークに流さない認証方式は → チャレンジレスポンス認証
- Q2 SAMLで認証を行い、アサーションを発行する側は → IdP（アイデンティティプロバイダ）
- Q3 普段と違う環境からのアクセス時だけ追加認証する方式は → リスクベース認証
- Q4 漏えいしたIDとパスワードの組を使う攻撃は → パスワードリスト攻撃
- Q5 パスワードを固定してIDを変える攻撃と、その狙いは → リバースブルートフォース攻撃。アカウントロックの回避
- Q6 リバースブルートフォースにロックアウトが効かない理由は → 同じIDで2回以上試行しないから
- Q7 レインボーテーブル攻撃への対策は → ソルト
- Q8 社内・社外を区別せず、毎回検証する考え方は → ゼロトラスト
- Q9 境界防御だけでは不十分な理由は → 内部に侵入された後の横展開を防げないから
- Q10 認証を集約し、退職者のID停止などを1か所で管理できるサービスは → IDaaS
- Q11 パスキーでサーバに登録しておくものは → 公開鍵だけ（秘密鍵は端末から出ない）
- Q12 パスキーがフィッシングに強い理由は → パスワードを送らないから
