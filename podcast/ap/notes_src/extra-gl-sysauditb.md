## 2. 核心：用語ごとの判断ルール

### 1. ITに係る全般統制と業務処理統制

ITの統制は、全般統制と業務処理統制の2つに分かれる。

![全般統制と業務処理統制の関係](img/extra-gl-sysauditb-1.svg)

- 全般統制：業務処理統制が有効に働く環境を整える統制。例：システムの開発・保守の管理、運用管理、アクセス管理、外部委託の管理。
- 業務処理統制：個々の業務の処理が正しく行われるように組み込まれた統制。例：入力データのチェック、エラーデータの修正と再処理、マスタデータの管理。
- 入力・処理・出力の正確性と網羅性を確保するのが業務処理統制（R6春）。
- 補足：全般統制は「土台（環境）」、業務処理統制は「その上で動く、個別業務の中の仕組み」と覚える。
- 誤り：アクセス管理を業務処理統制とする誤り。アクセス管理は全般統制。

| 区分 | 目的 | 例 |
|---|---|---|
| 全般統制 | 業務処理統制が働く環境を整える | 開発・保守の管理、運用管理、アクセス管理、外部委託管理 |
| 業務処理統制 | 個々の業務処理を正しくする | 入力データのチェック、エラーの修正と再処理、マスタ管理 |

### 2. 監査調書・監査証拠・予備調査

監査調書は、監査人が実施した監査手続とその結果、関連資料を記録したもの。監査の結論の根拠になる。

- 監査調書：監査意見を裏付ける証拠として作成し、適切に保管する（R5秋・R6春）。
- 監査証拠：監査の結論を裏付ける、十分かつ適切な証拠。
- 予備調査：本調査の前に、監査対象の実態を把握するために行う。結果をもとに監査手続を決める（R6秋）。
- 補足：流れは「予備調査 → 本調査（監査手続で証拠を集める）→ 監査調書に記録 → 監査報告」。
- 誤り：「監査調書は監査対象部門が作成する」は誤り。作成するのは監査人。

### 3. システム監査基準・システム管理基準（令和5年改訂）

システム監査人の行動規範と手続（監査基準）、管理者が整備すべき管理策（管理基準）を定めた経済産業省の基準。

- 令和5年に改訂され、ITガバナンスやアジャイル開発、クラウドなど新しい環境に対応した。
- 午後での問われ方：監査の根拠として「どの基準に照らすか」が問われる。近年の午前では令和5年版が出典になっている。
- 出題実績：R7春 午前問60（システム管理基準 令和5年）、R7秋 午前問58（システム監査基準 令和5年）。

### 4. 生成AI利用のガバナンス

生成AIの利用ルール、入力してよい情報、出力の確認方法などを決めて管理すること。

- 機密情報の入力による漏えい、誤った出力の利用、著作権の侵害がリスクになる。
- 午後での問われ方：監査では「利用ルールがあるか」「守られているか」「出力を人が確認しているか」を確かめる。
- 補足：ルールの有無、遵守の状況、出力の確認の3点で確かめる、と整理できる。

### 5. アジャイル開発の監査

短い反復で開発する場合も、要件・品質・変更の管理が機能しているかを確かめる監査。

- 文書が少ないため、バックログやレビュー記録、テスト結果など実際の作業記録を証拠にする。
- 午後での問われ方：「どの記録で確かめるか」を本文の資料名から選ぶ。

### 6. 監査手続の基本（午後）

監査証拠を集める方法。ドキュメントレビュー、インタビュー、ウォークスルー、テストデータ法など。

![記録の承認と関係者の把握を別々に確かめる](img/extra-gl-sysauditb-2.svg)

- 記録の「承認の有無」と、関係者が「把握しているか」を別々に確かめるのが定番。
- 午後での問われ方：照合する資料の組合せ（例：各管理表と点検表）が問われる（R7秋 午後問11）。
- 補足：記録（書類）をレビューして承認を確かめ、関係者にインタビューして把握を確かめる。1つの方法だけでは、どちらかが確かめられない。

## 3. 思い出しクイズ

- Q1 入力データのチェックやエラーの修正・再処理は、全般統制か業務処理統制か → 業務処理統制
- Q2 システムのアクセス管理は、全般統制か業務処理統制か → 全般統制
- Q3 業務処理統制が有効に働く環境を整える統制は → 全般統制
- Q4 監査人が実施した手続と結果を記録したものは → 監査調書
- Q5 本調査の前に監査対象の実態を把握する調査は → 予備調査
- Q6 監査調書を作成するのは誰か → 監査人
- Q7 システム監査基準・管理基準が改訂された年は → 令和5年
- Q8 生成AIの監査で確かめる3点は → ルールがあるか、守られているか、出力を人が確認しているか
- Q9 アジャイル開発の監査で、証拠にする記録の例は → バックログ、レビュー記録、テスト結果
- Q10 記録の「承認の有無」と関係者の「把握」を確かめる方法は → ドキュメントレビューとインタビューを組み合わせる
