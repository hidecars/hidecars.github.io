## 2. 核心：用語ごとの判断ルール

### 1. システム監査基準と監査人の独立性

システム監査は、独立かつ専門的な立場のシステム監査人が、情報システムのガバナンス・マネジメント・コントロールを点検・評価・検証し、結果を報告する活動。

- 独立性：監査人は監査対象から独立していなければならない。外観上の独立性（組織や利害関係）と精神上の独立性（公正で客観的な判断）がある。
- 監査人は「評価と助言（改善提案）」をする。改善を実施するのは監査対象の部門。
- システム監査基準（令和5年）：ガバナンス、マネジメント、コントロールの3つの視点から検証・評価する（R7秋）。
- 判断の尺度として使うのはシステム管理基準（令和5年）。
- 誤り：「監査人が自ら改善を実施する」は誤り。独立性を失う。
- 誤り：「監査対象部門の担当者が自部門を監査する」は独立性がなく誤り。

### 2. 監査手続と監査技法

監査手続は、監査技法を使って監査証拠を集める具体的な手順。

- ウォークスルー法：データの生成から入力・処理・出力・活用までのプロセスと、組み込まれたコントロールを、書類や記録をたどって確かめる（R3秋・R6秋に同じ問い）。
- インタビュー法：関係者に質問して回答を得る。
- 突合・照合法：関連する記録同士を突き合わせる。
- 網羅性（漏れも重複もないこと）の確認：伝票の一連番号とシステムに入力されたデータを突き合わせる。
- テストデータ法：監査人が用意したデータをプログラムで処理させ、結果を予想と比べる。
- 誤り：「網羅性の確認で、入力データの内容が正しいかを見る」は正確性の確認で、網羅性ではない。

### 3. フォローアップ

監査報告で示した改善提案について、監査対象部門の改善の状況を、監査人が後から確かめる活動。

- 監査人は改善の実施状況を確認する。改善の責任と実施は監査対象部門にある（R6秋・R7秋）。
- 改善が遅れている場合も、監査人は自分で改善しない。状況を確かめ、必要に応じて報告する。
- 誤り：「フォローアップとして監査人が改善計画を作成し実施する」は誤り。

### 4. ITに係る全般統制と業務処理統制

ITの統制は、全般統制と業務処理統制の2つに分かれる。

- 全般統制：業務処理統制が有効に働く環境を整える統制。例：システムの開発・保守の管理、運用管理、アクセス管理、外部委託の管理。
- 業務処理統制：個々の業務の処理が正しく行われるように組み込まれた統制。例：入力データのチェック、エラーデータの修正と再処理、マスタデータの管理。
- 入力・処理・出力の正確性と網羅性を確保するのが業務処理統制（R6春）。
- 誤り：アクセス管理を業務処理統制とする誤り。アクセス管理は全般統制。

### 5. 監査調書・監査証拠・予備調査

監査調書は、監査人が実施した監査手続とその結果、関連資料を記録したもの。監査の結論の根拠になる。

- 監査調書：監査意見を裏付ける証拠として作成し、適切に保管する（R5秋・R6春）。
- 監査証拠：監査の結論を裏付ける、十分かつ適切な証拠。
- 予備調査：本調査の前に、監査対象の実態を把握するために行う。結果をもとに監査手続を決める（R6秋）。
- 誤り：「監査調書は監査対象部門が作成する」は誤り。作成するのは監査人。

- Q1 監査人が監査対象から離れていなければならない性質は → 独立性
- Q2 改善を実施するのは監査人か監査対象部門か → 監査対象部門
- Q3 システム監査基準（令和5年）の3つの視点は → ガバナンス、マネジメント、コントロール
- Q4 データの生成から活用までのプロセスとコントロールをたどって確かめる技法は → ウォークスルー法
- Q5 受注入力に漏れも重複もないことを確かめる方法は → 伝票の一連番号と入力データを突き合わせる
- Q6 監査人が用意したデータを処理させ結果を比べる技法は → テストデータ法
- Q7 フォローアップで監査人が行うことは → 改善の実施状況を確認する
- Q8 改善の実施責任は誰にあるか → 監査対象部門
- Q9 入力データのチェックやエラーの修正・再処理は、全般統制か業務処理統制か → 業務処理統制
- Q10 システムのアクセス管理は、全般統制か業務処理統制か → 全般統制
- Q11 監査人が実施した手続と結果を記録したものは → 監査調書
- Q12 本調査の前に監査対象の実態を把握する調査は → 予備調査
