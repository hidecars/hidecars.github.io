# 令和6年度春期 午後 問5 ネットワーク／クラウドサービスを活用した情報提供システムの構築

## 1. 覚えるキーワード3つ
- MQTT：TCP上で動き、ヘッダが小さく、多数の機器から1か所へ送る通信に向くIoT向けプロトコル
- スループット：FWなどが単位時間に処理できる通信の量
- コネクション数：FWなどが同時に処理・保持できる接続元の数

## 2. 状況
- L社が、全国10,000台のIoT機器から気象データを集め、S社のクラウドで分析・提供する新システムを作る。
- IoT機器から1分ごとにデータが送られ、データ収集用サーバへ通信が集中する。機器や利用者が増えると、FWなどで処理遅延が起こるおそれがある。
- 通信を最小限だけ許可するFWのルールを設計し、負荷分散と性能指標の管理を行う。

## 3. 分野の核心

| 場面 | ありがちな誤答 | 正解の考え方 | 根拠になる本文の言葉 |
|---|---|---|---|
| IoT機器から多数のデータを集める | 一般的なHTTPを選ぶ（設問1(2)は正答率が低かった） | ヘッダが小さく、多対1の通信に向くMQTTを選ぶ | プロトコルヘッダサイズが小さい、多対1通信 |
| 通信量の増加で処理が遅れそう | 帯域だけを見る | FWの性能は「スループット」と「コネクション数」の2つで管理する（設問3(2)は正答率が高かった） | 単位時間に処理できる通信の量、同時に処理できる接続元の数 |
| 機器・利用者が増えても耐えたい | 1台を高性能にする | サーバを増やして分散(スケールアウト)する。そのためにロードバランサーを置く | スケールアウト |

## 4. 解答キーワード一覧

| 設問 | 問われていること | 決め手のキーワード |
|---|---|---|
| 1(1) | 1時間当たりの最大データ量 | 300(Mバイト) |
| 1(2) | IoT機器向けのプロトコル | MQTT |
| 2(1) | FWルールの送信元・宛先(a〜c) | a 200.a.b.13／b 200.c.d.101／c TCP/443 |
| 2(2) | 適用されるFWルールの項番 | 4、7 |
| 3(1) | 通信が集中するボトルネックの機器(d) | FW |
| 3(2) | 管理する2つの性能指標(e・f) | e ウ(スループット)／f ア(コネクション数) |
| 3(3) | スケールアウトに必要な機能 | エ(ロードバランサー) |

## 5. 用語

| 用語 | 一言の意味 |
|---|---|
| MQTT | TCP上で動く、軽量なIoT向けの通信プロトコル |
| LPWA | 省電力で広範囲に届くIoT向けの無線通信 |
| ステートフルパケットインスペクション | 通信の流れを把握し、対応する応答だけを自動で通すFWの機能 |
| スループット | 単位時間に処理できる通信の量 |
| コネクション数 | 同時に保持・処理できる接続元の数 |
| ロードバランサー | サーバへの通信を振り分けて負荷を分散する装置 |

## 6. 思い出しクイズ
- Q1 10,000台が1分ごとに500バイトを送るとき、1時間当たりの最大データ量は → 300Mバイト
- Q2 HTTPよりヘッダが小さく、TCP上で動く多対1向けのIoTプロトコルは → MQTT
- Q3 通信量が増えたとき、FWで管理する「単位時間の処理量」の指標は → スループット
- Q4 FWで管理する「同時に処理できる接続元の数」の指標は → コネクション数
- Q5 サーバをスケールアウトさせるときに追加する装置は → ロードバランサー

※採点講評：設問1(2)は正答率が低かった。設問3(2)は正答率が高かった。
